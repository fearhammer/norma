# Обработчик заявок Norma для PHP-хостинга

Статус: подготовлен для установки на REG.RU. В GitHub Pages PHP не выполняется.
До установки и проверки почты `PUBLIC_FORM_ENDPOINT` остаётся пустым: формы явно предлагают отправку через почтовую программу.

## Установка

1. Уточнить корень сайта и рабочий HTTPS-адрес хостинга. Не менять DNS действующего сайта ради установки обработчика. Если домен пока обслуживается Tilda, использовать отдельный HTTPS-поддомен хостинга.
2. В корне сайта создать `api/forms/` и загрузить **только** `index.php` и `lib.php`. Требуется PHP 8.0+ с JSON, hash и настроенным `mail()`.
3. Рядом с корнем сайта, **вне публичного каталога**, создать `norma-private/`. Скопировать туда `config.example.php` под именем `forms-config.php`. Если папка находится в другом месте, задать серверную переменную `NORMA_FORMS_CONFIG` с абсолютным путём.
4. Сгенерировать на сервере секрет: `php -r "echo bin2hex(random_bytes(32));"`. Вставить его в `secret`. Никогда не помещать секрет в GitHub, `public/` или `PUBLIC_*`.
5. У каталога `norma-private` должны быть права 700, у конфигурации — 600; владелец должен совпадать с пользователем PHP. Обработчик создаёт `forms-state.json` в этом же каталоге. Сохранять файл между обновлениями: он предотвращает повторную отправку и ограничивает частоту.
6. Проверить, что хостинг разрешает `mail()` с отправителем `mail@norma-studio.ru`, и что письмо действительно доходит в этот ящик. Успех `mail()` означает принятие в очередь, не подтверждение доставки. Если хостинг требует SMTP-аутентификацию, до включения формы заменить транспорт на SMTP и хранить настройки вне публичного каталога.
7. После проверки установить переменную репозитория GitHub Actions `PUBLIC_FORM_ENDPOINT` в полный HTTPS-адрес обработчика, например `https://<адрес-хостинга>/api/forms/`, и запустить публикацию. Для локальной сборки использовать `.env`.
8. Отправить одну явно обозначенную тестовую заявку через опубликованную страницу, подтвердить её получение, проверить тему, все поля, Reply-To и сообщение об успехе. Дополнительно проверить ошибку сети: поля должны сохраниться.

## Содержимое письма

- Получатель: `mail@norma-studio.ru`.
- Тема: `Заявка с сайта Norma`.
- Имя, email, Telegram, сайт компании, услуга и страница отправки.
- Reply-To — проверенный email посетителя. Получатель и тема зафиксированы на сервере.

## Защита

- Проверка Origin по точному списку и ограничение размера запроса 8 КБ.
- Проверка типов, длин, UTF-8, email и запрет управляющих символов/внедрения заголовков.
- Honeypot; подписанный сервером токен, связанный с IP и Origin, сроком 30 минут и минимальным ожиданием 3 секунды.
- Одноразовый токен, блокировка параллельных дублей и повторной отправки одинаковых полей в течение 10 минут.
- 30 запросов за 10 минут на IP; 3 заявки за 15 минут и 10 за сутки на IP; 5 за час на email; общий предел 200 заявок в сутки.
- Состояние хранится с блокировкой файла; в нём только HMAC-хеши и время, без содержимого заявок и открытых IP/email. Ошибки хранилища закрывают отправку.

Это базовая многослойная защита, а не гарантия отсутствия спама. Целенаправленный бот может получить токен и выдержать паузу. При такой атаке дополнительно подключить CAPTCHA с обязательной серверной проверкой. Origin сам по себе не защищает от запросов вне браузера.

Обработчик использует `REMOTE_ADDR`, не доверяет присланному посетителем `X-Forwarded-For`. Если перед PHP есть обратный прокси/CDN, сначала настроить доверенные прокси и проверить реальный IP, иначе лимит может стать общим для всех посетителей.

## Проверка без отправки настоящих писем

```sh
php -l server/forms/index.php
php server/forms/tests.php
node server/forms/http-test.mjs /absolute/path/to/php
```

Тесты проверяют содержимое письма, подмену получателя/темы, инъекцию заголовков, неверные поля, токены, лимиты, дубли, ошибки почты и хранилища. Они используют подставной транспорт и временный файл состояния. HTTP-тест дополнительно запускает локальный PHP и SMTP-приёмник: проверяет CORS, реальные HTTP-ответы и собранное письмо. SMTP-тест рассчитан на Windows PHP; на Linux нужен тестовый sendmail-транспорт.

Документация `mail()`: https://www.php.net/manual/en/function.mail.php
